# REST API

API основан на [спецификации OTUS](https://github.com/OtusTeam/highload/blob/master/homework/openapi.json). Регистрация требует поле `gender`. Маршрут `/user/me` возвращает анкету владельца токена.

| Метод и путь | Запрос | Ответ 200 | Ошибки запроса |
| --- | --- | --- | --- |
| `POST /user/register` | JSON с полями анкеты и `password` | `{"user_id":"<UUID>"}` | `400` — некорректные данные |
| `POST /login` | JSON `{"id":"<UUID>","password":"<пароль>"}` | `{"token":"<токен>"}` | `400` — некорректные данные, `404` — неверная пара UUID и пароля |
| `GET /user/search` | Query-параметры `first_name` и `last_name`, публичный доступ | Массив анкет | `400` — некорректные данные |
| `GET /user/get/{id}` | UUID в пути, публичный доступ | Анкета | `400` — некорректный UUID, `404` — анкета отсутствует |
| `GET /user/me` | Заголовок `Authorization: Bearer <токен>` | Анкета владельца токена | `401` — требуется действительный токен, `404` — анкета отсутствует |

## Поиск анкет

`GET /user/search?first_name=Конст&last_name=Оси` применяет оба префикса. Параметры обязательны. Удаляются начальные и конечные пробелы. Каждый префикс должен иметь длину от 1 до 100 символов и не содержать NUL. Поиск регистрозависимый. Символы `%`, `_` и `!` обрабатываются буквально.

Ответ содержит массив с полями `id`, `first_name`, `second_name`, `birthdate`, `biography` и `city`. Порядок определяется возрастанием UUID. При отсутствии совпадений возвращается `200` с пустым массивом.

## Регистрация

Тело запроса регистрации.

```json
{
  "first_name": "Анна",
  "second_name": "Иванова",
  "birthdate": "1995-04-12",
  "gender": "female",
  "biography": "Книги и путешествия",
  "city": "Алматы",
  "password": "Homework-demo-2026!"
}
```

Все поля обязательны. Дата имеет формат `YYYY-MM-DD` и ограничена текущей датой UTC включительно. У текстовых полей анкеты удаляются начальные и конечные пробельные символы. Результат должен быть непустым и не содержать NUL. Максимальная длина имени, фамилии и города — 100 символов, пола — 50, интересов (`biography`) — 2000.

Пароль для регистрации и входа содержит от 8 до 128 символов. Пароль из одних пробельных символов отклоняется. Нулевой UUID и значения некорректного формата в `POST /login` и `GET /user/get/{id}` возвращают `400`.

Анкета в ответах `/user/get/{id}` и `/user/me` содержит поля `id`, `first_name`, `second_name`, `birthdate`, `gender`, `biography` и `city`. Непрозрачный bearer-токен ASP.NET Core действует один час. Примеры и проверки входят в [Postman-коллекцию](../SocialNetwork.postman_collection.json).

## Друзья, посты и лента

Маршруты в таблице, кроме `GET /post/get/{id}`, требуют заголовок `Authorization: Bearer <токен>`. Отсутствующий или недействительный токен приводит к ответу `401`.

| Метод и путь | Запрос | Ответ 200 | Ошибки запроса |
| --- | --- | --- | --- |
| `PUT /friend/set/{user_id}`, `PUT /friend/add/{user_id}` | UUID друга | Пустой ответ | `400` — некорректный UUID, собственный UUID или отсутствующий пользователь |
| `PUT /friend/delete/{user_id}` | UUID друга | Пустой ответ | `400` — некорректный или собственный UUID |
| `POST /post/create` | JSON с полем `text` | UUID поста в виде JSON-строки | `400` — некорректный текст |
| `PUT /post/update` | JSON с полями `id` и `text` | Пустой ответ | `400` — некорректные данные, пост отсутствует или принадлежит другому пользователю |
| `PUT /post/delete/{id}` | UUID поста | Пустой ответ | `400` — некорректный UUID, пост отсутствует или принадлежит другому пользователю |
| `GET /post/get/{id}` | UUID поста | Объект поста | `400` — некорректный UUID, `404` — пост отсутствует |
| `GET /post/feed` | Целочисленные query-параметры `offset` и `limit` | Массив постов друзей | `400` — некорректные параметры |

Связь с другом направленная. Повторное добавление существующей связи и удаление отсутствующей связи возвращают `200`. Текст поста содержит от 1 до 4096 кодовых единиц UTF-16. Строки из одних пробельных символов и строки с NUL отклоняются.

Объект поста содержит `id`, `text` и `author_user_id`. Лента содержит до 1000 последних постов друзей в порядке убывания времени создания и UUID. Изменение текста сохраняет позицию поста. Значения по умолчанию — `offset=0` и `limit=10`. Допустимый `offset` начинается с 0, допустимый `limit` — с 1. Смещение за пределами ленты возвращает пустой массив.

## Личные диалоги

Оба маршрута требуют заголовок `Authorization: Bearer <токен>`. Инициатор определяется по токену. Параметр `user_id` содержит UUID собеседника.

| Метод и путь | Запрос | Ответ 200 |
| --- | --- | --- |
| `POST /dialog/{user_id}/send` | JSON с обязательным полем `text` | Пустое тело |
| `GET /dialog/{user_id}/list` | Без тела | Массив объектов с полями `from`, `to`, `text` |

Текст должен содержать от 1 до 4096 кодовых единиц UTF-16. Строки из одних пробельных символов и строки с NUL отклоняются. Ошибка формата, нулевой, собственный или неизвестный UUID возвращают `400`. Отсутствующий или недействительный токен приводит к `401`. При отсутствии настройки шардов, отсутствующем маршруте или временной ошибке PostgreSQL API возвращает `503` с полями `message` и `request_id`.

Ответ чтения включает оба направления переписки и сортируется по времени записи и UUID сообщения в порядке возрастания. Пустой диалог возвращается как `[]`. Чтение возвращает полный диалог. Проверка на локальном стенде описана в [отчёте ДЗ №5](homework-5/README.md).
