# ADR-0004. Кеш ленты друзей

Статус — принято. Дата — 2026-11-26.

## Контекст

Лента должна содержать до 1000 последних постов друзей пользователя. После изменения поста или связи следующее чтение должно отражать результат записи.

## Решение

Один экземпляр API хранит в памяти снимки до 1000 последних постов на автора и собранную ленту на пользователя. У записей общий оценочный бюджет в 64 МиБ и абсолютное время жизни 5 минут. При промахе ленты приложение читает список друзей из основного PostgreSQL, загружает отсутствующие снимки пачками до восьми авторов и объединяет отсортированные снимки в памяти. Между пачками сохраняются 1000 последних кандидатов. Пагинация применяется к собранной ленте.

Записи и холодная сборка выполняются под общим асинхронным затвором. Запись поста инвалидирует снимок автора и ленты его подписчиков. Запись связи инвалидирует ленту инициатора. Инвалидация выполняется до освобождения затвора. Попадание в кеш ленты обслуживается без обращения к PostgreSQL.

После инвалидации идентификатор ранее кешированной ленты помещается в `Channel<Guid>` внутри процесса. Очередь вмещает до 1024 задач. Один фоновый обработчик последовательно читает задачи и использует тот же путь сборки, что и GET. Если чтение уже восстановило ленту, обработчик использует готовый снимок. Успешная запись новой ленты в кеш фиксируется в журнале обработчика.

## Следствия

Переполнение очереди и ошибка обработчика оставляют восстановление ленты запросу GET. Очередь хранится в памяти процесса. После перезапуска API лента восстанавливается из PostgreSQL при первом чтении. То же происходит при промахе после истечения срока записи или вытеснения. Прямые записи в БД требуют перезапуска API для немедленного сброса снимков. Согласованность обеспечивается в пределах одного экземпляра API при изменении постов и связей через его маршруты. Общий затвор сериализует записи и холодную сборку.
